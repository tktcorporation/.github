# Email Scoring - メール品質・配信分析スキル

.eml ファイルまたはメール HTML を入力として、**Gmail Promotions タブ振り分けリスク**と**メールマーケティング品質**の2軸で分析・スコアリングするスキル。

ルールベースの定量チェックで客観的なスコアを出し、その結果を踏まえた LLM 分析で定性的な改善提案を行う。

## 重要な前提

- Gmail のタブ分類は ML ベースで非公開。**100%正確な予測は原理的に不可能**
- 本スキルは業界知見に基づくヒューリスティックスコアリングであり、実際の配信結果を保証するものではない
- エンゲージメント（開封率、クリック率、受信者の過去の行動）は最重要シグナルだが、メールの静的解析では評価できない。この限界をレポートに必ず明記する
- **Promotions タブ = 悪ではない**。「意図した配信先に届いているか」が本質的な問い

## 分析対象の取得

1. `.eml` ファイルパスが指定された場合: ファイルを読み込んでヘッダー + 本文を解析
2. HTML ソースが指定された場合: コンテンツ・構造を解析（ヘッダー分析はスキップ）
3. 指定がない場合: ユーザーにどのメールを分析するか確認

## 分析手順

### Phase 1: データ抽出（ルールベース）

.eml ファイルから以下の要素を抽出・集計する。

#### ヘッダー情報
- `From`, `Reply-To`, `Return-Path` のドメイン構成
- `X-Mailer`, `X-Intercom-Mailer` 等の送信ツールヘッダー
- `List-Unsubscribe`, `List-Unsubscribe-Post` の有無と形式
- `Precedence`, `X-Auto-Response-Suppress` 等のバルク送信ヘッダー
- DKIM/SPF/DMARC の認証結果（`Authentication-Results` から）
- `X-Mailgun-Tag`, `X-SES-*` 等の ESP 固有ヘッダー

#### コンテンツ情報
- 件名: 文字数、絵文字の有無、プロモーション語彙、パーソナライズトークン
- 本文テキスト: プロモーション語彙の出現回数と密度
- 画像: `<img>` タグ数、トラッキングピクセル（1x1）の有無、画像の総 width
- リンク: 総数、トラッキング URL の比率、ユニークドメイン数、CTA ボタン数
- HTML 構造: 総行数/サイズ、テーブルネスト深度、インラインスタイルの量

### Phase 2: ルールベーススコアリング

`references/scoring-criteria.md` の基準に基づき、11観点で定量スコアを算出する。

**カテゴリ A: Promotions タブリスク（6観点）**

| # | 観点 | 重み |
|---|------|------|
| A1 | ヘッダーシグナル | 高 |
| A2 | コンテンツ語彙 | 最高 |
| A3 | 件名 | 高 |
| A4 | HTML 構造 | 中 |
| A5 | リンク | 中 |
| A6 | 送信インフラ・認証 | 中 |

**カテゴリ B: メールマーケティング品質（5観点）**

| # | 観点 | 重み |
|---|------|------|
| B1 | コピーライティング | 高 |
| B2 | パーソナライズ | 中 |
| B3 | モバイル対応 | 中 |
| B4 | 配信停止・コンプライアンス | 高 |
| B5 | エンゲージメント設計 | 高 |

各観点は **0〜10 点**（0 = リスクなし/最高品質、10 = 最高リスク/要改善）で採点する。

### Phase 3: LLM 分析

Phase 2 のスコアと抽出データを踏まえ、以下を分析する:

1. **Promotions 判定の総合予測**: スコアだけでは捉えられないコンテキスト（メール全体のトーン、受信者との関係性を示唆する要素）を加味
2. **最もインパクトの大きい改善ポイント**: スコアが悪い観点のうち、改善効果が高いものを優先度付け
3. **具体的な改善提案**: 件名の書き換え例、構造の変更案、削除すべきセクションなど
4. **メールマーケティング観点の総評**: このメールが受信者にどう受け取られるか、開封・クリック・コンバージョンの各段階での強み・弱み

## 分析時の原則

### 公平な評価
- Promotions タブに入ること自体を「問題」として扱わない
- マーケティングメールが Promotions に入るのは Gmail の意図した動作
- 「このメールの目的に照らして、配信先は適切か？」という観点で判定する

### 実用的な提案
- 「こうすべき」だけでなく「こう書き換える」レベルまで具体化する
- 件名は必ず改善例を提示する
- トレードオフがある場合は明示する（例: パーソナライズを強めると制作コストが上がる）

### 限界の明示
- 静的解析で評価できない要素（エンゲージメント履歴、送信頻度、IP レピュテーション）は毎回注記する
- スコアに過度の確信を持たせない。「参考値」であることを伝える
