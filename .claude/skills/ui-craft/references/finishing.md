# 仕上げの検査

SKILL.md の手順 5 で、描画した画面に当てる検査の一覧。上から順に行う。上の検査で直したものが下の検査の結果を変えるので、順番を入れ替えない。

## 1. 構造：何が一番大事に見えるか

- **目を細める検査**：スクリーンショットを縮小するかぼかして見る。最初に目に入るものが、手順 2 で決めた最重要の要素か。違うなら、大きさ・太さ・色・位置のどれかで強弱を付け直す
- **3 秒の検査**：画面を 3 秒だけ見て、何をする画面かを一言で言えるか。言えないなら、見出しか主操作の置き方を直す
- **主操作は 1 つか**：同じ強さのボタンが並んでいたら、1 つを主、残りを従にする

## 2. 引き算：消して困らないものは消す

要素を 1 つずつ消したと想定し、失うものが無いものを消す。対象は次の順に見る。

1. 補助的なラベル・説明文・サブタイトル（`anti-patterns.md` の「ラベル・説明文」）
2. 区切り線と枠：余白で区切れているなら要らない
3. 影・グラデーション・背景の装飾：階層や状態を伝えていないなら要らない
4. アイコン：隣の文字と同じことを言っているなら要らない
5. 同じ操作への 2 つ目の入り口

消してから、1 の検査をもう一度行う。引き算で強弱の関係が変わることがある。

## 3. 揃い：ずれは数 px でも雑に見える

- 左端：同じ列にある要素の左端が揃っているか。アイコン付きの行と無い行で文字の開始位置がずれていないか
- ベースライン：横に並ぶ文字・アイコン・入力欄の高さの基準が揃っているか
- 余白の段階：使っている余白の値を列挙し、決めた段階の外の値が無いか
- 繰り返し：同じ種類の部品（カード、行、ボタン）の内側の余白・角丸・影が同じか

## 4. 中身：極端なデータで崩れないか

手順 2 で用意した次のデータを入れて描画する。

- 最長の名前・タイトル（折り返すか、省略するかが意図どおりか）
- 0 件、1 件、大量の件数（スクロール・ページ送りの位置）
- 大きな数値と負の数（桁区切り、桁揃え）
- 画像が無い、読み込めない場合

## 5. 幅と環境：1 つの条件だけで判断しない

- 狭い幅（375px 前後）と広い幅（1280px 以上）。中間の幅（768px 前後）でも、折り返しの切り替わりで崩れないか
- ライトとダーク（対応していれば）。ダークで影が見えなくなったり、枠が強すぎたりしないか
- 文字を 200% に拡大したとき、はみ出しや重なりが起きないか

## 6. 状態：操作の途中も画面の一部

- hover・focus・active・disabled のそれぞれを実際に表示して見る
- loading・empty・error を表示して見る（`anti-patterns.md` の該当節）
- キーボードだけで主操作までたどり着けるか。フォーカスの順序が見た目の順序と一致しているか

## 7. 別の目：意図を知らない読み手に見せる

自分の検査で直すものが無くなってから行う。実装の意図を知らない読み手（サブエージェントなど）にスクリーンショットだけを渡し、次を答えさせる。コードや要件を渡すと、読み手が意図を補ってしまい検査にならない。

- 最初に目に入るのは何か
- 何をする画面に見えるか
- 次に何をすればよいか
- 迷う箇所、意味が分からない箇所はどこか

答えが意図と食い違った箇所は、1 の検査に戻って直す。
