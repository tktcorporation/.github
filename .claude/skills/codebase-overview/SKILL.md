# コードベース俯瞰

設計・レビューに入る前に、依存構造と共有語彙を上から見る。局所のコードだけを読んで方針を決めると、
呼び出し元の前提を壊したり、既にある語彙を無視して似た型を増やしたりする。

## 使い方

```bash
# 変更方針をこれから決めるとき。全体像を出す
bun .claude/skills/codebase-overview/scripts/codebase-overview.ts

# 変更するファイルが決まっているとき・レビューで差分の影響範囲を見たいとき。
# 対象は複数渡せる
bun .claude/skills/codebase-overview/scripts/codebase-overview.ts worker/src/commands/event-add.ts

# 循環や孤立だけ見たいとき。repo map を省いて依存グラフだけ出す
CODEBASE_OVERVIEW_NO_MAP=1 bun .claude/skills/codebase-overview/scripts/codebase-overview.ts
```

初回は npx / uvx が外部ツールを取得するため待たされる。以降はキャッシュが効く。
所要時間の大半は依存グラフの取得（ワークスペースごとの madge 起動）が占めるので、
`CODEBASE_OVERVIEW_NO_MAP=1` で repo map を省いてもほとんど変わらない。
出力を短くしたいときに使う。

対象ディレクトリの外にあるファイルでも、`REPO_MAP_EXTENSIONS`（既定は `rs` と `py`）に
含まれる拡張子なら受け入れる。依存グラフは持たない言語なので madge は起動せず、
見出しの下に「依存グラフの対象外」と出したうえで repo map だけを出す。

## 出力の読み方

パスはどのセクションもリポジトリルート相対で揃えてある。目に留まったファイルは、
そのままコピーしてこのスクリプトの引数に渡せる。

**循環依存** — 相互に依存しているファイル。ここへ変更を入れると、初期化順や import 順に依存した
壊れ方をする。新しい循環を増やしていないかは、レビューで必ず見る。1 行 1 循環で、
ワークスペースをまたぐ循環も同じ一覧に 1 度だけ現れる。

**依存の集中** — 依存先が多い順。1 ファイルが広い前提を巻き込んでいる位置で、変更の影響が読みにくい。
ここに手を入れるなら、周辺のテストを先に確認する。

**どこからも参照されていないファイル** — 次の 4 つが混ざる。知らない名前だけを拾って追う。

- エントリポイント（`index.ts`、`main.tsx`、各 CLI スクリプト）— 必ずここに出る
- テストからしか使われていないもの — 全体像ではテストを除いて数えるため
- 対象ディレクトリの外から読まれるもの — 消すと壊れる。ビルドの入口（`web/src/design-sync-entry.ts`
  を読むのは対象外の `web/vite.lib.config.ts`）と、import されず tsconfig 経由で読まれる
  ambient 型定義（`web/src/vite-env.d.ts`）が該当する
- 消し忘れ

判定はワークスペースを横断する。`worker` のファイルが `scripts` からだけ import されていても、
孤立には出ない。横断するのは下記の対象ディレクトリ 3 つの範囲で、その外から使われている
ファイルは孤立に出る（「信頼できる範囲」を参照）。

**共有語彙（repo map）** — 多くの箇所から参照されている型・定数。依存グラフとは逆側を見ている。
依存グラフの上位に来るのは入口（多くを呼び出す側）で、こちらの上位に来るのは葉（多くから参照される側）。
新しい型を足す前にここを見て、同じ概念が既にあるなら再利用する。

## 信頼できる範囲

依存グラフは madge が TypeScript の import を静的に解決した結果で、**TS / TSX しか見ていない**。
これは madge の制約であり、この俯瞰スキル自体が他言語を扱えないわけではない。共有語彙
（repo map）は tree-sitter ベースで言語を選ばないため、`REPO_MAP_EXTENSIONS` に拡張子を
足せば対応できる（「メンテナンス」を参照）。次は落ちるので、グラフに出ないことを
「依存が無い」と読まない。

- 実行時に決まる依存（動的 `import()`、文字列でモジュール名を組み立てる箇所）
- TS 以外のファイル（`infra/tofu` の HCL、SQL、設定ファイル）— repo map 側にだけ現れる
- 対象ディレクトリの外にある import 元 — madge がスキャンするのは `worker/src` `web/src`
  `scripts` の中だけ

最後の 1 つは孤立ファイルの一覧を読み違えさせる。外からしか読まれないファイルは
「依存されている元: なし。」かつ孤立として並ぶ（「出力の読み方」を参照）。一覧は消してよい候補では
なく、対象ディレクトリの外に利用元が無いか確かめる対象として読む。

ワークスペース（`worker/src` `web/src` `scripts`）は tsconfig が別なので madge の実行も別に走るが、
循環依存・孤立ファイル・「依存されている元」はワークスペースを横断して判定する。
全体像はテストを除いて数え、ファイルを指定したときの依存先・依存元にはテストも含める
（影響範囲を見る用途ではテストも直す対象になるため）。

repo map は tree-sitter でシンボル名を抽出し、名前の一致でファイルを結ぶ。型解決はしないので、
**同名のシンボルは区別されない**。「だいたいこの辺に関係する」以上の精度は求めない。
正確な参照元が要るなら、TypeScript LSP でシンボルを引く。

対象は **git が追跡しているファイルだけ**で、未コミットの新規ファイルは警告なしに語彙から落ちる。
直前に自分で書いた型は出ないので、「同じ概念が既にあるか」をここで確かめるときは、
その回の作業で足した分を自分で補う。ファイルを指定したときはさらに、指定したファイル自身も
除かれる（aider が対話中のファイルとして扱う）。出るのはその周辺の語彙になる。

## メンテナンス

対象ディレクトリと tsconfig の対応は `scripts/codebase-overview.ts` 冒頭の `scopes` が持つ。
ここにある値は導入先リポジトリのワークスペース構成を書いたものなので、別のリポジトリでこのスキルを
使うときはまず自分のワークスペース構成に置き換える。ワークスペースを増やしたときも同様にここへ足す。
`scripts/self-test.ts` の `scopeFor` 系のテストは `scopes` の値をそのまま期待値に持つ
（設定とテストの整合性を見るテストのため）。`scopes` を書き換えたら、これらのテストの
期待値も合わせて書き換える。

依存グラフを持たない言語を repo map の対象に含めるかどうかは、同じ場所の
`REPO_MAP_EXTENSIONS` が持つ（既定は `rs` と `py`）。`scopes` と同様、この俯瞰スキルが対応する
言語を増やしたいときは導入先リポジトリでこの集合に拡張子を足す。

repo map から外すファイルはリポジトリルートの `.aiderignore` が持つ。生成された巨大な
型定義は参照の数こそ多いがこのリポジトリの語彙ではなく、外さないとトークン予算を
1 ファイルで使い切る。同種の生成物が増えたらここに足す。

スクリプトを変更したら検証する:

```bash
bun .claude/skills/codebase-overview/scripts/self-test.ts
```
